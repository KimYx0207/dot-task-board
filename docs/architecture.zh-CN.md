# 架构说明

[English](architecture.md) · [简体中文](architecture.zh-CN.md)

```text
已授权的快照导出 -> 校验 -> 看板只读模型 -> 项目画布
                            ^
                    可选的队列记录投影

已认证的浏览器 -> 需求存储 <- 已认证的 MCP 工具
                       |                 |
                可选事件发件箱      可选有限队列
                       |                 |
                注入的传输实现      注入的宿主适配器
```

## 职责边界

- 导出方提供获准使用的观察记录、时间和证据
- 领域层校验快照、Agent 关系、需求事件与队列转换
- 应用层在导入范围内计算关联、时效与数量
- 存储适配器持久化需求，以及可选的队列和事件记录
- HTTP 与 MCP 适配器提供范围明确的操作，不授予账号访问权或执行权限
- 浏览器负责项目选择、筛选、详情，以及接入后的需求保存
- 外部宿主负责认证、审批与实际执行，只有核实执行结果后才能报告正在运行或已经完成

`server.mjs` 与 `worker.mjs` 共用应用层和展示层代码。`scripts/build.mjs` 将代码与静态资源打包成 Worker。运行时快照、需求数据库和部署身份单独提供。

## 项目与关系

项目是导航和画布分组的主入口。任务与 Agent 的已记录关联，与表示 Agent 父子关系的 `parentAgentId` 分开展示。同属一个项目不能证明任务依赖或创建关系。自由填写的岗位名称不会生成新的 Agent 身份。

独立项目注册表为需求通道提供固定 ID、标准名称和可选别名。未配置注册表的项目仍可展示，但没有固定 ID 就不能接收需求。需求通道配置无效时，不应隐藏原本有效的快照。

六款生成式形象帮助区分 Agent 卡片。岗位未核实时，根据 Agent ID 确定展示形象，保持视觉稳定；这不表示已经推断出岗位，也不会创建新的 Agent 记录。

## 时间与覆盖范围

观察时间属于来源记录。导入时间表示快照何时整理，响应生成时间表示何时读取。刷新不能重写观察时间，未来时间或缺失时间也不能算作新鲜证据。

计数只描述本次导入的已知范围。跨项目出现的同一 Agent 在汇总中去重。未知覆盖范围不能变成全局总数，旧的运行记录会标为待核实。任务完成、Agent 最近成果、部署与业务验收分别表示。

## 需求与执行

需求存储保留提交原文、引用快照版本、原任务上下文和有顺序的状态事件。保存、读取、受理、分派与完成是不同转换。列表或读取操作不会自动确认已读。

可选队列先保存派发意图，再允许宿主执行，并限制同时占用的名额，保留原线程和原环境绑定。外部操作结果不明时，保留名额直到核对完成。宿主适配器是需要实现的接口，不是随仓库提供的原生调度器。浏览器提交不会直接调用它。

Events 是独立实验：持久化事件发件箱加上注入并获准的 Webhook 传输实现。打开配置或通过模拟测试，不代表真实回调或插件已经连接。详见[可选接入](integrations.zh-CN.md)。

## 通用部分与宿主特有部分

本地快照服务不依赖托管平台。Worker 可以使用兼容 D1 的 `DB` 绑定来存储需求和实验记录。某个宿主的私有站点配置、身份校验、数据库绑定及回调传输，属于部署方职责，不是通用默认配置。

Workbench 适配器只映射已经获准使用的导出数据，不连接 Workbench 会话、不复制执行引擎、不发现 Agent，也不读取私有对话。
