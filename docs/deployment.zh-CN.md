# 部署说明

[English](deployment.md) · [简体中文](deployment.zh-CN.md)

## 本地 Node 服务

`npm start` 只监听 `127.0.0.1`。使用 `DOT_BOARD_SNAPSHOT_PATH` 指向仓库之外的快照，或在服务端通过 `DOT_BOARD_SNAPSHOT` 提供 JSON 字符串。应用不会自动加载 `.env` 文件。

本地服务用于环回访问。不要为了远程访问而移除 Host 校验或直接暴露到公网；需要远程查看时，选择提供适当认证与授权的宿主。

## Worker 适配器

```sh
npm run build
```

该命令生成 `dist/server/index.js`，提供 `fetch(request, env)` 的 ESM Worker，其中仅包含应用代码和静态界面资源。部署由操作者单独决定，持续集成不会执行部署。

运行数据通过以下任一方式单独提供：

- `DOT_BOARD_SNAPSHOT`：完整 JSON 字符串
- `DOT_BOARD_SNAPSHOT_PARTS`：分块数量，配合 `DOT_BOARD_SNAPSHOT_0` 至最后一个分块

分块是应对宿主单值长度限制的传输方式，不是加密机制。敏感运行数据应通过宿主支持的秘密值机制保存。真实快照和托管项目身份不能提交到仓库。

Worker 没有内置账号系统。使用真实任务数据前，确认部署平台将完整页面及 `/api/board` 限制给预期访问者。隐蔽网址或隐藏链接不足以提供访问控制。

## 刷新行为

页面刷新按钮重读已提供的快照，不查询原生助手、不启动调度器，也不取得其他系统的访问权。导出或定期更新服务需要单独配置，并明确数据范围和访问策略。

## 验证边界

本地测试校验模型、输入边界、HTTP 行为和 Worker 请求处理。390 像素的预览框可辅助检查布局，但不是实际手机测试。声称生产或手机验收通过之前，应验证真实部署、登录边界和目标设备。
